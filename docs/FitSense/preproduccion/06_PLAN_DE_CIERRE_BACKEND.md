# 06 · Plan de cierre del backend

**Base:** `generation` en `77b9df3`. **Fecha:** 27/11/2026.

**Alcance.** Este plan solo recoge lo que **falta** o **hay que corregir**. Lo que ya existe y está verificado no se vuelve a desarrollar: recuperación de contraseña, eliminación de cuenta, consentimientos V63, generación asíncrona V58/V59, O20/V65, push y panel. Cuando una acción reutiliza código existente, se indica.

**Ninguna acción de este plan se ha ejecutado.** Respeta las restricciones de la orden: no cambia *prompts*, validadores, reglas O20 ni el catálogo, y no crea migraciones en esta orden. Las que necesitan una migración lo indican para una orden posterior.

## Criterios de prioridad aplicados

| Prioridad | Cuándo se asigna |
|---|---|
| **P0** | Sin resolverlo, no se puede empezar el piloto con personas reales: expone datos de salud, permite el acceso indebido, invalida el consentimiento o hace perder semanas de datos del estudio. |
| **P1** | El piloto puede arrancar con una mitigación operativa explícita, pero hay que corregirlo para un estudio estable de 12 semanas. |
| **P2** | Mejora que no compromete la seguridad ni la medición de la adherencia. |

Las decisiones que no son de código (equipo del estudio, comité de ética, asesoría legal) se marcan como **[Decisión]**. Ninguna se presupone.

- **P0-05 depende de P1-11** porque su criterio de aceptación necesita el reloj controlable y la ampliación V59, que toca el mismo planificador (`WeeklyCycleRecoveryScheduler` en V66). Hay que acordar quién implementa la recuperación del tick para no duplicarla. Puede que la ampliación V59 ya la cubra en parte: **revisarlo cuando se integre, antes de empezar P0-05**.
- **P0-03 (c)** cambia el contrato de registro. Mobile y backend tienen que desplegarse juntos, o el campo nuevo debe ser opcional hasta encender la exigencia.
- Las acciones que necesitan una migración (P1-05 rol de solo lectura, P1-09, P1-10, P2-02) van en órdenes separadas. La numeración tiene que coordinarse con V66.

## 3. Lo que ya está y no debe rehacerse

Recuperación de contraseña (V44_2, V61), eliminación de cuenta desde la app y la web (V60, V62), consentimientos versionados (V63), edad mínima, push FCM (V64), generación asíncrona resiliente (V58, V59), recuperación G08 por id, O20 con equivalencias y precauciones por ángulo e identificación posterior (V65), progresión y reincorporación, roles y aislamiento entre usuarios, HTTPS, cabeceras y CORS. El detalle y la evidencia están en `01_INVENTARIO_FUNCIONAL_BACKEND.md`.
